# 범용 사이트 구축 지침 세트

> **사용법**: 새 프로젝트를 시작할 때 이 폴더를 통째로 복사해 프로젝트 루트에 둔다.
> 그리고 `범용_03_작업지시서_템플릿.md`를 프로젝트 루트에 `작업지시서.md`로 복사해서 채운다.
>
> 최종 개정: 2026-09-08 · REV 1

## 이 폴더의 문서 3개

| 파일 | 성격 | 프로젝트마다 수정하나? |
|---|---|---|
| `범용_01_사이트구조사양.md` | **영구 규격.** 호스트·URL·canonical·사일로·페이지 블록·이미지·성능 예산 | ✕ 수정 금지. 개선 시 REV를 올려 이 폴더 원본을 갱신 |
| `범용_02_바이브코딩지침.md` | **AI 협업 규칙.** 근거 수준 표기, STOP 지점, 대량생성 위험, 색인 투입, 법적 리스크 | ✕ 수정 금지. 새 사고가 생기면 원본에 반영 |
| `범용_03_작업지시서_템플릿.md` | **프로젝트마다 복사해서 채우는 골격** | ○ 복사본을 채운다 |

## 충돌 시 우선순위

```
프로젝트에서 실측으로 확인된 사실   ← 가장 강함
        ↓
범용_01 사이트구조사양
        ↓
범용_02 바이브코딩지침
        ↓
프로젝트 작업지시서 (=03의 복사본)
```

**실측이 최상위인 이유**: 범용 문서는 일반론이다. 특정 프로젝트에서 직접 측정해 확인한 사실(예: "이 검색엔진은 이 조건에서 이렇게 동작한다")이 일반론과 어긋나면 **측정한 쪽이 맞다.** 단 그 실측 근거를 프로젝트 작업지시서에 날짜·방법과 함께 기록해야 인정된다.

## 절대 하지 말 것

**사양을 작업지시서에 복사해 넣지 말 것.** 두 곳에 같은 내용이 있으면 반드시 갈라지고, 그때부터 어느 쪽이 맞는지 아무도 모른다. 작업지시서에서는 **참조만** 한다.

```
✕  "URL은 하이픈 없이 붙여쓴다. 예: /밀양시민장례식장화환/"
○  "URL 정책은 사양 §1.3을 따른다."
```

## 새 프로젝트 시작 절차

1. 이 폴더를 프로젝트 루트에 복사
2. `범용_03_작업지시서_템플릿.md` → 프로젝트 루트에 `작업지시서.md`로 복사
3. `작업지시서.md`의 **§0 목적·성공기준**과 **§1 확정 결정사항**을 먼저 채운다
   - 도메인·호스트(www 여부)는 **빌드 전에 반드시 확정**한다. 나중에 바꾸면 canonical·사이트맵 전체를 다시 만들고 301이 필요하다 (사양 §1.1)
4. AI 도구 설정 파일(`CLAUDE.md`, `.cursorrules` 등)에서 이 문서들을 자동 로딩하도록 연결
   ```markdown
   작업 전 아래를 반드시 읽는다.
   @_범용지침_사이트구축/범용_01_사이트구조사양.md
   @_범용지침_사이트구축/범용_02_바이브코딩지침.md
   @작업지시서.md
   ```
5. 작업 시작. 매 세션 끝에 작업지시서의 **작업 로그**에 한 줄 남긴다
